# 設計メモ

[READMEに戻る](../README.md)

- PaperDIYファームウェアは `firmware/paperdiy/` に配置します。サーバと独立してMacからUSBで書き込みます。
- 初期仕様のStrata検算例と現fixtureは異なります。現行SPEC.mdには両者を区別して記載しています。現fixtureの期待値は Prefill「—」（未再利用トークンが512以上のリクエストも保存値もなし）、Context 約0.377%（247 / 64K）、VRAM 14.6 / 16 GB、RAM 61.7 / 79 GB、再利用率約73.846%です。fixtureは変更せず、仕様の検算例は別の合成入力でテストします。
- Prefillの仕様例は「約131」だけで元入力が不明なため、合成入力は例を再現する検証です。過去データそのものを復元したものではありません。
- Strata の相対時刻・当日判定にはJSONの `time`、xangiのペース・古さには引数の `now` を使います。実行マシンの時計・タイムゾーンには依存しません。
- 千トークン未満のContextは整数、以上は千単位の整数 `k`、容量は1024単位の整数 `K` とします。直近リクエストのpromptは1000単位・小数1桁の `k` 表記です。
- 使用率と整数表示は四捨五入（0.5切り上げ）。リセットまで0秒超60秒未満は期間にかかわらず「まもなく」、それ以上の短時間リセットの残り分は切り捨て、`resetsAt <= now` は「リセット済」として目安線と反転を無効にします。未来のリクエスト時刻は0秒前とします。
- 0%集約は丸める前の使用率がすべて厳密に0のgroupだけを対象にし、空のwindow一覧は集約しません。0%のgroupをプロバイダごとにまとめ、例えば「0%: Antigravity（Gemini, Argon, Claude・GPT）」と表示します。Antigravityの既知group IDはこの3つの短縮名に対応させ、その他のgroupはlabelから「共通枠」「専用枠」を除きます。プロバイダはUSAGE_ORDER、groupは元データの順を保ち、USAGE_HIDEを適用後に集約します。1行に溢れる場合は末尾を「…」で省略します。
- 反転判定は丸める前の使用率とペースの厳密な `>` 比較です。指定順にないプロバイダは入力順を保って末尾に置きます。
- 欠落・null・非数値・非有限値やゼロ以下の分母からは計算値を作らず、表示は「—」とします。複合表示では各欠落値を「—」で置き換えます。取得日時が不明・不正なプロバイダは「(古)」にします。
- オフライン判定は最終取得成功から600秒以上。一度も成功していない場合はデータなしとして、オフライン判定をfalseにします。

- 画面は960×540のカード形式で、左約550px・右約400pxです。本文22px・リクエスト行高33px・decode棒グラフ300×40pxを使い、Decodeは54px、Prefillは通常24px・履歴値22pxです。状態は最大250pxを確保し、実際の文字幅からモデル名の表示幅を決めます。Generatingは24pxで省略せず、250pxを超える状態や長いモデル名は末尾を省略します。
- Decodeは数値を左、300×40pxの棒グラフを右に配置し、左右の内側パネル上端は72px、下端は455pxに揃えます。モデル名・状態は64pxのベースラインでタイトル行との余白を確保します。段間隔と外枠内の下余白は8px、左右の外枠下端は463pxです。フッターは外枠から8px空けた471〜534pxに置き、画面下に左右と同じ5pxを残します。最終リクエストの2行は32px間隔で、漢字の下にも余白を確保します。
- VRAM・RAMは22pxで容量と単位を表示します。容量とGBが1行に収まらない場合は、GBを見出しに移して数値幅を確保します。それでも長い容量は使用量と総量の2行にし、見出しを含むベースライン間隔を29pxにします。上段カードは高さ85pxとし、通常の1行表示は見出しと値を36pxのベースライン間隔で中央寄せします。上下の段との間隔は8pxを確保します。フォントを縮小せず値を保持します。片方でもGBを見出しへ移す場合は、容量と単位の幅を確保するため両メモリカードのチップアイコンを省き、見た目を揃えます。アイコン表示とメモリ描画は共通の文字幅判定を使います。
- キャッシュ再利用率は実際の計算値を数値とリングで示します。欠落時は「—」と輪郭のみです。端末の電池・RSSIは受信まで非表示とし、受信した数値を表示します。Wi-Fi接続状態を推測するアイコンは置きません。
- アイコンは描画コード内の独自の単純な図形です。ブランドロゴや外部画像は同梱しません。長いモデル名・見出しは22px以上を維持して末尾を省略します。右側は3つの2-windowグループを表示できる間隔とし、幅110pxのバーを使います。溢れるgroup数は0%集約と同じ末尾行に併記します。
- decodeは直近10件を古い順から描き、nullは空欄、全0ならidle、全nullなら—です。電力は140×32px・線幅2pxで、描画領域をカード内側に置き、下枠との間に余白を設けます。live t/s・GPU使用率のグラフは表示しません。
- AI利用量のPNG見出しはプランを省いた `display_heading` と幾何アイコンで表示します。Claudeは放射線、Codexは組み合わせた円、Antigravityは四方の星を使います。JSONの既存 `heading` は互換性のためプラン付きです。更新時刻は両エリアのタイトル行右上、AI利用量の取得失敗は直下の予約領域のベースライン64pxに表示します。モデル名・状態を含め本文の位置は失敗の有無で変えません。
- 16階調パレットは文字34・アイコン51・枠と区切り線102・棒85・利用量塗り119・外側背景238です。見出し帯は85に白255の文字・アイコン、警告行は見出しより濃い51に白文字で区別します。Prefill・VRAM・RAM・GPU・温度カードとフッター全体は白255で、電池・RSSI未受信時も白背景です。
- CLIのfixture履歴はサンプル周期が未定義なので30秒間隔と仮定します。実運用は実際の取得時刻を保存します。nullのグラフ点は補間せず、全0は平線です。
- `bat`・`rssi` は単一デバイスを想定します。取得失敗による状態更新も3画面キャッシュの更新契機に含めます。全画面の描画が成功した世代だけを採用し、GETでは再描画しません。
- `.env` の変数展開は行いません。設定値をそのまま扱い、パスの先頭のチルダのみ展開します。
- デプロイは `.env` をシェルとして実行しません。転送先の値を検証・引用し、ホーム全体やルートへの同期は拒否します。
- Piでの常駐、Macからのdeploy、PaperDIYへのUSB書き込み・実機表示・電池残量表示・カード形式のレイアウトは実機で確認済みです。ネットワークなしのテストではHTTP取得とSSH・rsyncをモックし、電池持続時間の長期計測は別途行います。

- Prefillは最新順のrequestsから `(prompt_tokens - reused) >= 512` の最初の1件を選びます。その1件の計算が不可能な場合や該当なしの場合はSQLiteの最後の有効値を使い、「131 t/s（10/28）」形式で表示します。保存値もなければ24pxの「—」です。
- 直近リクエストは画面ではHH:MM・状態・prompt→output・decode t/s・durationの1行、最大3件、22px・行高33px（1.5倍）です。時刻・状態は左揃え、prompt→output・t/s・秒は各列の固定右端で右揃えにし、JSONには日付情報も残します。
- 数値と単位は同一ベースラインで描画します。CJKフォントの度記号の末尾空白を詰め、48°Cが分離しないようにします。t/sの前には全箇所で半角スペースを入れます。電力上限は整数、expertsは前置、状態は先頭大文字とします。
- 見出しのproviderとgroupが同名ならgroup名を省き、古さの表示は維持し、プランはJSONのheadingだけに残します。windowラベルは5h・週に短縮します。
- 22pxを維持するため画面からPCIe・CPU数値・CPU/ディスクのグラフを省き、Contextは百分率だけにします。計算値・履歴保存は引き続き保持します。

- 有効PrefillのキャッシュはStrata取得成功時に同じSQLiteトランザクションで保存します。日付はpoll時刻ではなくリクエストのtimeをTZで変換します。古いリクエストの再送で保存日時を巻き戻さず、7日の時系列削除でも最後の1件は保持します。日時不明の有効値は「（—）」と表示します。
- `prefill`テーブルは既存DBに起動時に追加されます。再起動後、最初のStrata取得時から保存値を使えます。生の取得JSON自体は保存しません。

CLIで保存値の表示を確認する場合は、明示的に既存SQLiteを指定できます。読取専用で参照し、DBを新規作成したりfixtureの値を保存したりしません。初期版のDBにprefillテーブルがない場合は保存値なしとして扱います。

```sh
.venv/bin/python -m paperhub.render \
  --strata tests/fixtures/strata_monitor.json \
  --usage tests/fixtures/xangi_usage.json \
  --out out/paper.png --now 1793411985 \
  --history-db data/history.db
```

- Strata のキーは前後の空白を除き、ASCII 英数字と `-._~+/=` のみに制限します。引用符とエスケープを使わない代入で systemd と dotenv が同じ値を読み、JSON でエスケープされずに返るキーを失敗ログで伏せられるようにします。
- 失敗時刻はその周期の最後の失敗時刻です。Strata の 401/403 は認証・アクセス設定の診断を記録し、その周期のリトライを省きます。失敗フラグがあっても最終成功から300秒未満は非表示とし、一度も成功していない場合は「データなし」を維持します。診断ログはリトライ前後の各失敗時に記録します。
- ポーリング周期にはリトライ待ちと通信時間を含めます。キャンセル時はリトライせず終了し、途中の取得結果は成功確定まで保持データに反映しません。

- 任意のNTPサーバとPOSIX TZ規則は `secrets.h` で上書きでき、空欄時は `pool.ntp.org` / `UTC0` を使います。サンプルの代入値は空欄です。通信は仕様のLAN向けHTTPに対応し、HTTPSは対象外です。
- BtnAはGPIO4、BtnBはGPIO3のactive Low入力で、ext1のANY_LOWによる復帰を使います。押しっぱなしでの復帰ループを避けるため、スリープ前に最大2秒待ち、Lowのボタンだけその回のマスクから外します。両方がLowならタイマー復帰のみです。
- RTC時刻はESP32の内部RTCタイマーを使います。外付けRTCの有無には依存しません。昼夜の切替はスリープへ入る時刻で選びます。
- 受信は1MiBまでのPSRAMバッファに限定し、受信中30秒を超えた書き込みは拒否します。HTTP接続待ち3秒、読み取り待ち10秒も設けます。無通信時は読み取りタイムアウトが適用されるため、30秒は厳密な通信全体の期限ではありません。
- 全量受信前に表示を変更せず、起動時のclearと自動更新も無効にします。デコード検証用PSRAMは描画前に解放し、エラー時は右下だけを明示的に更新します。

## 3画面と復帰状態

表示中のviewはファームのRTC_DATA_ATTRだけに保持し、サーバはリクエストのviewからPNGを選ぶステートレスな構成です。Aとタイマーは保持したviewを更新、Bは次のview、A+Bはダッシュボードを要求します。deep sleep復帰以外の起動・リセットではダッシュボードへ初期化します。ext1の記録は最初のLowだけの場合があるため、RTCピンを通常入力へ戻した直後、シリアル待ちやM5.beginより前に両GPIOを読みます。ボタン復帰で他方もLowならBothに昇格し、タイマー・電源投入時はボタンレベルを画面切替に使いません。

要求した画面は、HTTP 200、X-Paper-Viewの一致、受信・CRC・デコード検証、全面描画の成功を経てから確定します。失敗時は保持viewを更新せず、旧画像に×と時刻を出します。Bによる失敗後も、次のBでは同じ次画面を再要求するため画面を飛ばしません。ヘッダがない旧サーバも失敗として扱います。ボタン操作後の読み込み中表示や独自UIは描きません。

[公式製品ページの回路図（K159-B_PaperDIY_sche.pdf）](https://docs.m5stack.com/en/core/PaperDIY_Assembly_Kit#schematics)の3ページで、GPIO3/4に3V3_L0へ接続した1MΩの外付けプルアップR41/R42を確認しました。ext1ではRTC電源ドメインが自動で維持されないため、RTC_PERIPH=ONとRTCピンの入力・内部プルアップ・プルダウン無効を明示します。復帰マスクの判別後は両ピンをrtc_gpio_deinitし、通常入力へ戻します。GPIO3は出力駆動しません。

M5Unified 0.2.26の[Power_Class.inl](https://github.com/m5stack/M5Unified/blob/0.2.26/src/utility/Power_Class.inl)を確認し、deepSleep(us, false)はext0/ext1の設定を変更せず、タイマーを追加してdeep sleepへ入ることを確認しています。表示のsleep処理を含むこの呼び出しを維持し、万一戻った場合はESP-IDFのタイマー設定とesp_deep_sleep_startへ進みます。内部プルアップを維持するRTC電源設定もこの経路では上書きされません。

## view別の描画検証とキャッシュ

受信データは、履歴とPrefillをステージしたSQLiteトランザクション内でsnapshotを作り、3画面すべてを描画して検証します。1画面でも例外が出れば書き込みをロールバックし、前のデータ・最終成功時刻を維持して従来の1回のリトライを行います。全画面成功後にDBをコミットし、同じsnapshotと3枚の生成済みPNGをまとめて採用します。検証用に作った画像は再描画せずキャッシュに使います。起動時と取得失敗確定時も、旧データから3画面をまとめて描画します。

詳細画面だけが必要とする日時変換などのエラーを受信確定前に検出するため、遅延描画から更新時の全画面検証へ変更しています。GETはキャッシュを返すだけです。単一プロセス・イベントループ内で、トランザクション中とキャッシュ更新中にawaitしないため、世代や未確定の履歴が混ざりません。

3画面はこの同じsnapshotを使います。リセットの相対時刻・日時、日付付きのリクエスト時刻、メモリバーに必要な既存の値は内部detailsに保持し、/paper.jsonからは除外して従来の返却内容を維持します。format_strata/format_usageの計算とSQLiteスキーマは維持し、履歴保存のコミットを描画成功後に揃えます。端末情報は全viewで保存し、従来どおり次のデータ更新時のsnapshotへ反映します。

Strata詳細のリクエストは既存の最大3件を維持し、日付付きで行高29pxにします。計算APIの件数は増やしません。詳細画面はCPU・PCIe・Context実数と百分率（小数1桁）も表示します。利用量詳細はUSAGE_HIDEを適用した全非ゼロgroupと、末尾の0%集約を表示し、最初に領域を超えたgroupから末尾をまとめて件数で省略し、後ろの小さいgroupへ飛び越しません。リセットは同じsnapshotの時刻を基準に相対時刻と日時を併記します。詳細画面だけに位置の3点と次画面名を表示し、既存ダッシュボードの画素は維持します。
